# TDCanvas「画布无线模式」产品需求文档

> 状态：第一阶段已开发，进入验收
> 产品形态：现有无限画布中的新增操作模式
> 核心规则：用户主动把指定节点结果设为 `Set`；同一画布内的其他节点才可 `Get`，无需连线，也不复制对象节点

## 1. 需求结论

这个方向可行，但不应让用户手动创建一份与结果重复的“对象”。

- 图片、视频、音频或文本节点持有可用结果后，由用户明确选择是否设为当前画布的全局 Set。
- 上传素材节点也可由用户主动 Set，便于生成结果与外部素材使用同一套交互。
- 消费节点保存稳定的来源节点 ID、输出口和可选版本，而不是保存一份媒体副本。
- 运行时才解析引用，因此来源节点更新后，默认读取它当前展示的最新成功结果。
- 无线模式隐藏连接端口和连线；连线模式继续完整保留，两者由用户在同一项目中明确选择。
- 来源更新不会自动触发下游生成，避免意外消耗余额。

用户界面使用“引用结果”“当前画布结果”等自然语言，不展示 `get()`、`set()` 代码。

## 2. 要解决的问题

1. 同一张角色图、场景图或视频需要被画布中多个节点重复使用。
2. 大画布中的跨区域长连线会交叉、遮挡素材和参数面板。
3. 用户关心使用的是哪份结果，而不是两个节点在画布上的距离。
4. 生成节点再次运行后，应让引用方自然跟随最新结果，不必重新连接。
5. Aitudou 与 ComfyUI 都需要使用同一套全局引用能力，不能各自实现一套孤立逻辑。

“我的资产”仍用于跨画布长期收藏；本需求只提供当前画布内的动态结果引用。

## 3. 产品目标

1. 只有用户明确 Set 的节点结果才会在当前画布中被发现。
2. 图片、视频、音频和文本输入无需连线即可引用兼容结果。
3. 一个来源可被任意数量的节点引用。
4. 引用关系可见、可移除、可排序，不成为不可排查的黑盒。
5. Aitudou 原生生成节点与 ComfyUI 暴露输入都能真实读取全局引用。
6. 老项目与已有连线不丢失；切换模式只改变交互和可视化。
7. 媒体继续复用现有本地缓存，不复制大文件、不发送本地路径给远程 API。

## 4. 非目标

第一阶段不包含：

1. 跨画布动态引用。
2. 对象更新后自动批量运行下游节点。
3. JavaScript 表达式或任意代码执行。
4. 独立的对象管理侧边栏。
5. 通用的多媒体历史版本锁定界面；图片历史仍沿用现有历史预览。
6. 删除现有连线模式。

## 5. 名词与语义

### 5.1 Set：用户主动发布节点结果

节点生成、上传或编辑成功并持有可解析内容后，用户可在节点工具栏点击“设为 Set”。只有完成该操作，它的当前结果才成为画布级可引用值。来源节点就是这个值的可视化载体，不新增重复节点。

用户可点击“取消 Set”。取消后该节点会退出无线引用列表，并移除指向它的现有无线引用，避免留下不可见但仍在生效的依赖。

来源节点标题是选择器中的显示名称；节点 ID 是持久化引用使用的稳定地址。

### 5.2 Get：消费节点全局引用

消费节点通过以下信息读取来源：

- `sourceNodeId`：来源节点稳定 ID。
- `outputPortId`：可选，插件或宏节点存在多个输出时用于精确定位。
- `targetInputId`：可选，ComfyUI 宏节点用于绑定具体暴露输入。
- `versionMode`：默认 `latest`；后续可扩展固定历史版本。
- `versionId`：固定版本时使用。

Get 不绘制连线。运行时统一解析为现有 `NodeGenerationInput[]` 或 ComfyUI 输入值。

### 5.3 当前结果

来源节点当前展示且最后一次成功保存的内容。再次生成期间继续保留旧结果并显示遮罩；只有新结果成功后才切换当前值，失败或取消不会污染引用。

## 6. 模式设计

工具栏提供：

- `连线模式`
- `无线模式`

### 6.1 连线模式

- 保留端口、连线、连线流光和现有连接操作。
- 旧画布默认保持该模式。

### 6.2 无线模式

- 隐藏节点端口、已保存连线和创建连线入口。
- 图片、视频、音频等生成面板显示“引用结果”入口。
- 选择器只展示当前画布中由用户 Set、拥有可用结果且类型兼容的其他节点。
- 结果节点标题旁显示轻量全局对象标识。
- 切回连线模式时原有连线恢复，不删除数据。

### 6.3 输入来源规则

1. 新增普通对象引用时，该目标节点现有的输入连线会被移除，避免同一输入产生歧义。
2. ComfyUI 以 `targetInputId` 为粒度；同一暴露输入在对象引用与连线之间二选一。
3. 执行时对象引用优先于同槽历史连线，界面操作同时清理冲突来源。
4. 上传素材和生成结果在选择器中有不同标签，但底层使用同一资源协议。

## 7. 核心用户流程

### 7.1 使用生成结果

1. 节点生成图片、视频、音频或文本。
2. 用户在该节点工具栏点击“设为 Set”。
3. 用户切换到无线模式，在另一个生成节点点击“引用结果”。
4. 搜索或浏览结果，点击加入。
5. 引用以缩略图卡片出现；多参考图支持拖拽排序和单独移除。
6. 用户运行消费节点，系统在提交瞬间解析来源节点当前结果。

### 7.2 来源再次生成

1. 来源节点运行期间继续保留上一次成功结果。
2. 新结果成功后，来源节点更新当前内容并写入现有历史记录。
3. 跟随 `latest` 的引用下次运行时自动取得新结果。
4. 不自动运行任何引用节点，也不产生隐式费用。

### 7.3 ComfyUI 暴露输入

1. 每个可连线的图片、视频、音频或文本输入旁显示全局引用入口。
2. 选择器按输入类型过滤来源。
3. 选择结果后保存 `targetInputId`，并移除该输入的旧连线。
4. 运行 ComfyUI 宏节点时，媒体先通过已有安全下载层读取，再上传到当前 ComfyUI 环境的输入目录。
5. ComfyUI 输出继续写入原生图片、视频、音频或文本结果节点；用户可选择其中需要复用的结果进行 Set。

## 8. UI/UX 要求

1. 连线模式与无线模式统一收纳在左侧“画布外观”面板，由用户明确选择当前模式；底部缩放控制区不再重复展示模式入口。
2. 结果选择器跟随节点定位和缩放，不固定在屏幕坐标。
3. 支持按节点标题搜索。
4. 候选项展示缩略图、完整标题、资源类型以及“生成结果/上传素材”标签。
5. 已选结果显示勾选状态，再次点击可移除。
6. 不能引用当前节点自身，不能选择没有可用内容的节点。
7. 类型不兼容的结果不进入候选列表。
8. 生成运行中或存在未解决任务时沿用现有输入锁定规则。
9. 对象引用卡片继续复用现有参考素材预览、排序和模型数量限制提示。

## 9. 数据结构

```ts
type CanvasInputMode = "connections" | "objects";

type CanvasObjectReference = {
  id: string;
  sourceNodeId: string;
  outputPortId?: string;
  targetInputId?: string;
  versionMode?: "latest" | "pinned";
  versionId?: string;
  createdAt?: string;
};
```

- `CanvasProject.inputMode` 保存项目当前交互模式。
- `CanvasNodeMetadata.objectReferences` 保存该消费节点的 Get 关系。
- `CanvasNodeMetadata.canvasSetEnabled` 保存来源节点是否已由用户 Set。
- 来源节点仍是内容、缓存路径和历史版本的唯一权威数据。
- 第一阶段不新增 CanvasObject 表或第二份对象 store，避免内容与节点状态双写。

## 10. 统一解析架构

```text
节点运行
  └─ Input Resolver
       ├─ Connection Reference（已有连线）
       ├─ Object Reference（当前画布全局 Get）
       └─ Self / Direct Upload（节点自身内容）
              ↓
        统一资源输入
              ├─ Aitudou 请求适配
              └─ ComfyUI 输入上传与参数填充
```

要求：

1. Aitudou 不单独维护对象逻辑，继续消费统一生成输入。
2. ComfyUI 只在暴露输入绑定层保留 `targetInputId`，资源解析复用画布通用解析器。
3. 引用只指向来源，不复制 Blob、Data URL 或磁盘文件。
4. 删除来源节点时同步清理所有指向它的对象引用。
5. 删除消费节点不影响来源节点。
6. 保存、撤销、重做和项目恢复必须包含 `inputMode` 与对象引用元数据。

## 11. 本地缓存与安全

1. 生成结果继续优先使用 Tauri 应用数据目录或开发环境 `data/media-cache` 中的稳定文件。
2. 运行时读取远程历史结果时继续走既有受控下载与回填逻辑。
3. 本地路径不直接发送给 Aitudou；ComfyUI 输入通过本地原生客户端上传。
4. 由于引用指向来源节点，来源节点仍存在时媒体缓存自然被现有引用收集逻辑保护。
5. 文件缺失时阻止运行，并用来源节点标题说明哪个全局结果不可用。

## 12. 第一阶段验收标准

### 12.1 Aitudou 图片闭环

1. 切换无线模式后所有节点端口与连线隐藏。
2. 只有用户主动 Set 的已生成图片和上传图片出现在“引用结果”选择器中。
3. 空图片节点可选择一张或多张结果，预览、排序和移除正常。
4. 不创建连线也能构建真实图片参考输入。
5. 来源节点更新后，下一次运行读取最新内容。

### 12.2 ComfyUI 闭环

1. ComfyUI 暴露媒体/文本输入可选择当前画布兼容结果。
2. 保存的引用准确绑定对应输入 ID。
3. 无输入连线时也能读取资源、上传到 ComfyUI 并写入工作流参数。
4. ComfyUI 结果节点完成 Set 后成为其他节点可引用的来源。

### 12.3 兼容性

1. 连线模式行为不变。
2. 切换模式不丢失已有连线或对象引用。
3. 删除来源节点不会留下失效引用。
4. 重启桌面客户端后模式和引用仍能恢复。
5. 自动化测试不得发起付费生成。

## 13. 后续阶段

1. 为图片、视频、音频和文本统一历史版本，提供 `pinned` 版本 UI。
2. 在候选列表中增加最近使用、类型筛选和引用次数。
3. 增加“查看被哪些节点引用”和画布定位能力。
4. 允许插件通过输出口协议暴露多输出候选。
5. 增加来源更新提示和运行快照中的实际版本记录。

## 14. 审查结论

需求已经收敛为“用户选择哪个节点 Set，当前画布再全局 Get”。这一方案比默认公开全部结果更可控，也与现有结果节点、本地缓存和历史预览自然兼容。第一阶段以稳定节点引用实现无线复用，同时保留连线模式作为可视工作流；不会引入第二份媒体状态，也不会让结果更新自动触发付费任务。
