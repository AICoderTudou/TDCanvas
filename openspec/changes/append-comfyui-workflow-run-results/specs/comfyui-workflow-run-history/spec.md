## Purpose

本 capability 用于保证本地 ComfyUI 工作流的每次串行运行都在画布上形成独立、可追溯且不会被后续运行覆盖的原生结果节点与输出连线。

## ADDED Requirements

### Requirement: 每次运行追加独立结果
系统 SHALL 在本地 ComfyUI 工作流每次成功提交并取得唯一 `prompt_id` 后，为该次运行的每个暴露输出分配独立的原生结果节点；后续运行 MUST NOT 复用含有既有运行结果的节点。

#### Scenario: 串行运行三次生成三个视频
- **WHEN** 用户等待前一次运行结束后，连续三次点击同一个仅含单视频输出的本地工作流运行按钮，且三次运行均成功
- **THEN** 系统执行三次 ComfyUI 任务，并从同一视频输出端口保留三条连线和三个分别对应三次运行的视频结果节点
- **THEN** 三个视频节点均可独立播放、下载和作为画布资源继续使用

#### Scenario: 第一次运行使用空结果节点
- **WHEN** 工作流已有随节点创建的空结果节点，且用户首次成功运行该工作流
- **THEN** 系统可以将该空节点分配给本次运行并填入结果，而不额外留下无内容的重复节点

#### Scenario: 手动删除结果后再次运行
- **WHEN** 用户删除某个历史结果节点后再次成功运行工作流
- **THEN** 系统为新运行追加新的结果节点和连线，且不重建用户已经删除的历史结果

### Requirement: 历史结果保持不变
系统 MUST 将每次运行的结果与该次运行的唯一标识关联，并且后续运行的准备、排队、执行、成功、失败或取消状态 SHALL 只修改当前运行的结果节点。

#### Scenario: 第三次运行不覆盖前两次结果
- **WHEN** 同一工作流已经保留两个成功视频，用户完成第三次成功运行
- **THEN** 前两个视频节点的内容、本地文件路径、成功状态和运行标识保持不变
- **THEN** 第三次结果写入新的视频节点

#### Scenario: 新运行失败
- **WHEN** 工作流已有成功历史结果，而新运行在提交前或执行期间失败
- **THEN** 所有既有成功结果保持可用且不变
- **THEN** 系统只在存在本次运行结果节点时将本次节点标记为失败

#### Scenario: 新运行被取消
- **WHEN** 工作流已有成功历史结果，而用户停止当前运行
- **THEN** 所有既有成功结果保持可用且不变
- **THEN** 停止操作只影响当前运行及其结果节点

### Requirement: 兼容现有画布结果
系统 SHALL 将现有画布中已经包含内容或运行标识的 ComfyUI 结果节点视为历史结果，并 MUST NOT 在升级后的下一次运行中覆盖该节点。

#### Scenario: 现有单结果画布升级后运行
- **WHEN** 用户打开升级前已经生成一个视频结果的画布并再次成功运行同一工作流
- **THEN** 系统保留原视频节点和连线，并追加第二个视频节点和第二条连线

### Requirement: 追加结果保持可辨识且不重叠
系统 SHALL 将同一工作流的新结果节点放置在既有受管结果之后，使多个结果节点在默认布局下保持可见且不相互覆盖。

#### Scenario: 三个视频结果的默认布局
- **WHEN** 同一工作流依次生成三个视频结果且用户未移动这些结果节点
- **THEN** 三个视频节点位于工作流输出侧并按生成顺序排列，节点边界不重叠

### Requirement: 单工作流保持串行执行
系统 SHALL 继续限制同一个本地工作流节点同一时刻只有一次活动运行，不新增并发运行队列。

#### Scenario: 当前运行尚未结束
- **WHEN** 用户查看一个正在运行的本地工作流节点
- **THEN** 系统继续提供停止当前运行的操作，而不允许从该节点同时提交第二次运行
- **THEN** 用户可在当前运行结束后再次点击运行以追加下一份结果
